# Remove Storybook — Feature Spec

**Status:** Proposed · **Date:** 2026-10-26 · **Scope:** `apps/web` (Storybook config, stories, dev dependencies) plus root config and `README.md`

## 1. Summary

Storybook was added as a seed when the component library lived in `packages/ui` (commit `2732ac4`). It never grew beyond that seed: three stories (`Button`, `Input`, `Modal`) for 21 base components, no addons, and no CI step that builds or tests it. Meanwhile the in-app `KitchenSink` page (`#/kitchen-sink`) already renders every base component and icon inside the real app, with real styles, routing, and store.

Storybook adds unnecessary bloat. Its two dev dependencies pull in **175 of the 613 packages** in `package-lock.json` (about 29%) and grow the lockfile from about 6,500 lines to about 9,300. That includes a second esbuild and TypeScript toolchain, `react-docgen`, and ~24 MB in `node_modules`. Every `npm ci` (locally, in CI, and in the release workflow) pays for it. It also costs config: a `.storybook/` folder, two npm scripts in each of two `package.json` files, a dedicated ESLint block, and `storybook-static` ignore entries in three files.

Remove Storybook entirely. `KitchenSink` stays the place to see components in isolation.

This is a **tooling removal, not a feature**. No component, styling, or app behavior changes.

## 2. Goals

1. **Smaller install.** Drop `storybook` and `@storybook/react-vite` and every transitive package only they need.
2. **Less config.** No `.storybook/` folder, no Storybook scripts, no Storybook-specific lint or ignore rules.
3. **One way to preview components.** `KitchenSink` is the documented way to see base components.
4. **Nothing else changes.** The app, tests, lint, and build behave exactly as before.

## 3. Non-goals

- Changing any component's API, markup, or CSS.
- Changing or expanding `KitchenSink`. It already covers every component the stories cover.
- Replacing Storybook with another tool (Ladle, Histoire, etc.).
- Rewriting historical docs in `docs/features/` that mention Storybook. They describe past work and stay as written.

## 4. Why not keep it?

| Argument for keeping            | Why it doesn't hold here                                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Develop components in isolation | `KitchenSink` does this, inside the real app shell with real CSS tokens.                                                    |
| Living documentation            | 3 of 21 components have stories. The docs are mostly missing and nobody is maintaining them.                                |
| Visual or interaction testing   | No addons, no test runner, no Chromatic, and nothing in CI runs Storybook.                                                  |
| Low cost to keep                | It costs ~29% of the dependency tree and keeps forcing config changes. The `packages/` removal had to move and re-point it. |

If we need a component workbench later, adding Storybook back is a short, well-documented job (`npm create storybook@latest`).

## 5. Changes

### 5.1 Files deleted

| Path                                                     | Notes                                                  |
| -------------------------------------------------------- | ------------------------------------------------------ |
| `apps/web/.storybook/main.js`                            | Storybook config                                       |
| `apps/web/.storybook/preview.js`                         | Imports `../src/index.css`; nothing else depends on it |
| `apps/web/src/base/components/Button/Button.stories.jsx` |                                                        |
| `apps/web/src/base/components/Input/Input.stories.jsx`   |                                                        |
| `apps/web/src/base/components/Modal/Modal.stories.jsx`   |                                                        |

### 5.2 Config

| File                    | Change                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `apps/web/package.json` | Remove the `storybook` and `@storybook/react-vite` devDependencies, and the `storybook` and `build-storybook` scripts  |
| `package.json` (root)   | Remove the `storybook` script                                                                                          |
| `package-lock.json`     | Regenerated by `npm uninstall` (175 packages removed)                                                                  |
| `eslint.config.js`      | Remove the `**/storybook-static/**` ignore and the `apps/web/.storybook/**` globals block                              |
| `.prettierignore`       | Remove `storybook-static`                                                                                              |
| `.gitignore`            | Remove `storybook-static/`                                                                                             |
| `README.md`             | Drop "with Storybook" from the workspace table and the `npm run storybook` line; point to the KitchenSink page instead |

### 5.3 Unaffected

- `.github/workflows/ci.yml` and `release.yml` never reference Storybook.
- `scripts/scaffold.js` doesn't generate stories.
- `apps/web/vite.config.js` has no Storybook settings.

## 6. Acceptance criteria

- [ ] `apps/web/.storybook/` and all `*.stories.*` files are gone.
- [ ] `grep -ri storybook` over the repo (excluding `node_modules`, `.git`, and `docs/`) returns nothing.
- [ ] `package-lock.json` has no `storybook` or `@storybook/*` entries.
- [ ] A clean `npm ci` succeeds.
- [ ] `npm run format:check`, `npm run lint`, `npm test`, and `npm run build` pass.
- [ ] `npm run dev` starts, and `#/kitchen-sink` renders every component as before.
- [ ] `npm run tauri:dev` still starts the desktop app.
